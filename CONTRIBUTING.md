# Contributing

Thanks for improving this template.

## Contribution principles

- Keep it practical and lightweight.
- Prefer reusable templates over private stories.
- Use sanitized examples only.
- Do not add secrets, personal data, or account-specific identifiers.
- Do not add third-party dependencies without a clear reason.

## Pull request checklist

Before opening a PR:

- [ ] The change is useful for more than one person/team.
- [ ] No secrets or private data are included.
- [ ] Placeholders are clearly marked with angle brackets.
- [ ] Markdown headings and links are readable.
- [ ] Security implications are documented.
- [ ] If the change affects workflows, `README.md` or examples are updated.

## Suggested review questions

1. Can a new user understand what to copy and where to put it?
2. Does the example accidentally reveal private operations?
3. Is the workflow safe for local drafting before public publishing?
4. Does this make the project more credible as OSS, not just as an application artifact?
